# Country & Weather Explorer

A Flutter app to browse countries, view details, current weather and a map of
each country. It uses Firebase Authentication and GetX for state management.

## Features

- **Firebase Auth**: email/password sign in and sign up, form validation, friendly
  error messages, session persistence (stays logged in after a restart) and logout
  with a confirmation dialog.
- **Countries**: the full list from REST Countries v5, showing flag, name, capital
  and region, with pull to refresh. The list shows as a grid on wide screens.
- **Search & filters**: search by name (debounced), region chips and a
  favorites-only filter. Each has its own empty or no-results state.
- **Country details**: flag, capital, region, population, currency, latitude and
  longitude.
- **Weather**: current temperature, condition, humidity and wind speed from
  Open-Meteo, using the country's latitude and longitude. It loads on its own, so
  the screen stays usable if the weather request fails, and has a retry button.
- **Map**: an OpenStreetMap preview (flutter_map) with a marker, plus a full-screen
  interactive map.
- **Local storage** (SharedPreferences): favorite countries, the last 5 searched
  countries and the last selected country ("Continue exploring").
- **Error handling**: no internet, timeouts, server and auth errors,
  empty or invalid responses, and missing data (shown as `N/A`, never a crash).

## Setup

1. **Install packages**

   ```bash
   flutter pub get
   ```

2. **Configure Firebase**

   - Create a Firebase project and enable **Authentication → Email/Password**.
   - Generate `lib/firebase_options.dart` (it replaces the placeholder):

     ```bash
     dart pub global activate flutterfire_cli
     flutterfire configure
     ```

   - Sign in with an account created in the Firebase Console, or use
     **"Create one"** on the login screen.

3. **REST Countries API key**

   REST Countries removed its old keyless versions (v1–v4). v5 needs a free key
   from https://restcountries.com/sign-up. The key lives in a git-ignored file,
   so create it before the first build:

   ```bash
   cp lib/core/config/api_keys.example.dart lib/core/config/api_keys.dart
   ```

   In `api_keys.dart`, rename the class to `ApiKeys` and paste your key. You can
   also override it at run time:

   ```bash
   flutter run --dart-define=COUNTRIES_API_KEY=your_key_here
   ```

   The weather API (Open-Meteo) and map tiles (OpenStreetMap) need no keys.

```
├── core/
│   ├── config/app_config.dart    # API URLs, keys, timeouts
│   ├── dependencies.dart         # Registers services & repositories (Get.put)

│   ├── models/                   # Country, Currency, Weather (fromJson)
│   ├── repositories/             # CountryRepository, WeatherRepository
│   └── services/                 # AuthService (Firebase), StorageService (prefs)

│   ├── login/

│   └── details/
├── routes/                       # Route names + GetPage list with bindings
└── widgets/                      # Shared UI: StatusView, FlagImage, SectionCard, CountryMap
```

### How data flows

```
View (GetView + Obx)  →  Controller (GetxController, Rx state)
                      →  Repository (API → Dart models)
                      →  ApiClient (Dio, connectivity check, error mapping)
```

- Views contain only UI. They read reactive state with `Obx` and call controller
  methods.
- Controllers hold the business logic and a `ViewStatus`
  (`loading / success / empty / error`) for each section. The details screen
  keeps a separate status for weather.
- Repositories call the API and return typed models. Every failure becomes an
  `AppException` with a user-friendly message.
